# ADR-0003: Vite as build and dev tool

**Status:** Accepted
**Date:** 2026-05-27
**Slice:** cross-cutting
**Refines:** —
**Category:** Tech stack

## Context

V3 needs a build process that compiles TypeScript, transforms JSX, produces a PWA bundle and
provides a dev server with HMR. `docs/architecture/concept-brief.md §1` sets Vite explicitly.

> _This decision was set explicitly in the concept brief without alternatives being
> examined — Vite is the de facto standard for Preact + TypeScript + PWA projects._

## Decision

Vite (currently v8) is used as build tool and dev server. Configuration in
`v3/vite.config.ts`. The JSX transform is set to `preact/jsx-runtime`. `vite-plugin-pwa`
generates the service worker (ADR-0005).

## Consequences

**Positive:**

- HMR is fast (~ms instead of seconds): good DX for iterative development.
- TypeScript is transformed natively (no extra `tsc` watch pipeline needed).
- Plugin ecosystem: `vite-plugin-pwa` is well integrated.
- `npm run build` produces a production-ready bundle in under a second (measured at the time of the ADR; varies with hardware and plugin versions).

**Negative / Trade-offs:**

- Vite uses esbuild for transforms (not tsc for type checking). Type errors are not always
  shown immediately in the dev server — `npm run build` calls `tsc -b` and is the
  authoritative type check.

## Alternatives considered

**Parcel:** less configuration, but weaker plugin support for PWA.

**webpack:** mature and flexible, but a slower dev server and more config overhead. No
advantage for this use case.
