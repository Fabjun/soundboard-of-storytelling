# ADR-0053: Exception management

**Status:** Accepted
**Date:** 2026-09-29
**Slice:** cross-cutting
**Refines:** —
**Category:** Test infrastructure & workflow

## Context

Project rules are enforced by lint rules, guard tests and ADRs. Deliberate exceptions to
those rules existed in several ad-hoc forms: three `eslint-disable` directives without a
reason, `prettier-ignore` without a reason, tool ignore lists without comments, an
unnecessary `.prettierignore` entry for all `*.config.ts/js` files (they were already
formatted), config files silently excluded from linting, and design exceptions written as
prose inside ADRs. Only test quarantine and the untested-module list followed a scheme.
An exception without a scheme is where structure erodes unnoticed (CLAUDE.md §Guiding
priorities).

## Decision

Industry practice: every suppression carries a justification in the code
(`@eslint-community/eslint-plugin-eslint-comments` rule `require-description`, format
`-- <reason>`; Microsoft code analysis `SuppressMessage(Justification = …)`); unused
suppressions are errors (ESLint `linterOptions.reportUnusedDisableDirectives`); no blanket
suppressions (`no-unlimited-disable`); temporary exceptions carry an expiry condition
(eslint-plugin-unicorn `expiring-todo-comments`).

1. **Two kinds.** _Permanent_ exception: rule + reason (+ ADR if it is a design decision).
   _Temporary_ exception: rule + reason + **mandatory** `BACKLOG "<heading part>"` — the
   BACKLOG entry states when it is reviewed (our expiry condition).
2. **Form per kind** (native syntax of each tool, same information):

   | Kind                                 | Form                                                                                                                           | Enforced by                                                              |
   | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
   | ESLint suppression                   | `// eslint-disable-next-line <rule> -- <reason>`                                                                               | `require-description`, `no-unlimited-disable`, unused directives = error |
   | TypeScript suppression               | `@ts-expect-error <reason>` only; `@ts-ignore` banned                                                                          | typescript-eslint `ban-ts-comment` (recommended)                         |
   | Formatting                           | comment line with the reason directly above `// prettier-ignore`                                                               | `testGuards.test.ts`                                                     |
   | To-do marker                         | `TODO` / `FIXME` / `XXX` only with `BACKLOG "…"`                                                                               | `testGuards.test.ts`                                                     |
   | Test quarantine                      | skip/fixme/todo/fails with `BACKLOG "…"` (procedure in `testing.md`)                                                           | lint + `testGuards.test.ts`                                              |
   | Module without unit test             | `EXEMPT` entry with reason                                                                                                     | `testGuards.test.ts`                                                     |
   | Tool ignore list                     | trailing/preceding comment with the reason per entry                                                                           | register review                                                          |
   | Design / rule exception              | `## Exceptions` table in the owning ADR (Exception, Reason, Reference, Review)                                                 | register review                                                          |
   | Hook bypass (`git push --no-verify`) | only for probe pushes without app code, or when the hook already ran green for the same state; stated in chat / commit message | not detectable — rule in CLAUDE.md                                       |

3. **Register:** `docs/development/exceptions.md` is generated by `npm run sync:exceptions`
   (part of `sync:docs`, pre-commit, CI up-to-date check) from all of the above — it cannot
   go stale.
4. **Config files are linted** (`*.config.{js,ts}`, without type information) and formatted;
   ignore lists contain generated output only.

## Consequences

**Positive:**

- Every exception is visible in one place, with reason and review trigger.
- New undescribed or stale suppressions fail lint / guards at commit time.

**Negative / Trade-offs:**

- One more dev dependency (`@eslint-community/eslint-plugin-eslint-comments`).
- Tool ignore lists and ADR exception tables are checked by review, not by a rule.

## Alternatives considered

**eslint-plugin-unicorn `expiring-todo-comments`:** supports dates and versions, not our
review triggers (slices); a `BACKLOG "…"` reference plus the BACKLOG entry covers it
without another plugin.

**Hand-written exception list:** rejected — it would drift; the register is generated.
